技術文書の書き方

本書は、エンジニアが README、設計書、手順書などの技術文書を書くときに必要な考え方と技法をまとめたものである。読者と目的を定めて構成を決めるところから、誤解されにくい文の書き方、表記のそろえ方、文書の種類ごとの書き方、レビューと保守までを順に扱う。

本編

  • 第 1 章 はじめに
    • 本書の目的
    • 対象読者
    • 技術文書とは
    • 技術文書の種類
    • 悪い技術文書が生むコスト
    • 本書の構成
  • 第 2 章 書く前の準備
    • 読者を定める
    • 目的を一文で書く
    • 文書の種類を選ぶ
    • 情報を集め、取捨選択する
  • 第 3 章 構成を組み立てる
    • 結論を先に書く
    • 見出しを設計する
    • 段落を組み立てる
    • 文書を分割してリンクで結ぶ
  • 第 4 章 文を書く
    • 一文一義で書く
    • 主語と述語を対応させる
    • 修飾語の係り先を明確にする
    • 曖昧な表現を避ける
    • 事実と意見を区別する
    • 否定と受け身を使いすぎない
    • 指示語の指す対象を明確にする
  • 第 5 章 表記をそろえる
    • 文体を統一する
    • 用語を統一する
    • 表記ゆれをなくす
    • 英数字と記号の書き方をそろえる
    • スタイルガイドと用語集を用意する
  • 第 6 章 文以外の要素を使い分ける
    • 箇条書き
    • 表
    • 図
    • コード例
    • 注記
    • リンク
  • 第 7 章 文書の種類別の書き方
    • README
    • 設計書
    • API リファレンス
    • 手順書
    • 障害報告書
    • Issue、プルリクエスト、コミットメッセージ
  • 第 8 章 レビューと保守
    • セルフレビュー
    • 他者によるレビュー
    • ツールによる検査
    • Docs as Code
    • 文書の陳腐化を防ぐ
